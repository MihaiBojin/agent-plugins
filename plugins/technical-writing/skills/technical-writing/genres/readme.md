# README, tutorial, how-to and reference

Reader: someone evaluating, installing or learning. How-tos, overviews and
concept guides work better short for newcomers. Tutorials and references can
be long, because readers scan references.

## Shape

A README has seven parts:

1. One sentence on what the project is and who it is for.
2. Install.
3. A quickstart, with its expected output.
4. Tasks.
5. Configuration.
6. Limits.
7. Links.

## Rules

- The introduction states what the document covers, what it assumes, and what
  it does not cover. Check the draft against that introduction.
- Use real headings with no skipped levels, link text that names its target,
  and alt text on every screenshot (`navigable`).
- Sample code builds, does what it claims, and is tested like production code.
- Give a range of samples, from a minimal example to a realistic one, with an
  anti-example where a mistake is likely.

To check an existing README against the code it describes, use the readme
plugin.
