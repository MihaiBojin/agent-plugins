# Dialogue implementation plan

The approved design is an explicit-only conversation plugin with a Python standard-library state tool. Settings and thread records belong to each client session. Full agent-rules remains available through its installer; a separate limited profile excludes conversation behavior.

## Constraints

No automatic skill invocation. Installation alone applies no response policy. Session disable wins over saved defaults. Settings inspection is read-only. Never change the user's live configuration while testing. No commits or pushes in this task.

## Deliverables

- [x] `plugins/dialogue/lib/state.py`, `threads.py`, and `cli.py`: locked JSON updates, isolated session snapshots, validated settings, thread transitions, and renderer. Run subprocess tests first, then implement and rerun.
- [x] `plugins/dialogue/bin/dialogue`, client hook configurations, and `skills/dialogue/`: explicit entry point and opt-in restoration. Exercise each configured hook with real session payloads and inspect cold, resumed, disabled, and compacted sessions.
- [x] Both manifests, README, changelog, release inventory, generated catalogs, and Python test integration. Run repository checks and install with both clients into temporary configuration directories.
- [x] Separate agent-rules worktree: full/limited selection, separate artifacts, safe home symlink migration, profile status and rollback. Run installer tests in temporary homes and inspect output.

## Verification

Exercise concurrent thread allocation; close/reopen and spent option IDs; corrupt state without data loss; read-only settings; changes to defaults without affecting saved sessions; rendering with compact and focus settings; and preservation of other clients' sessions. Review the skill with an independent agent using a temporary state directory.

## Results

Both clients installed dialogue 0.1.0 in temporary homes. Packaged and installed hooks were exercised while disabled and enabled. Python tests cover persistence, concurrent allocation, corrupt records, fork isolation, and spent options. The independent conversation test closed the selected runtime thread, advanced to the install decision, and retained the hidden backlog. Agent-rules profile tests cover full/limited switching and preservation of personal instructions.
